## 프로세스 구성 — 인터넷 출구는 하나

```
사용자 ─▶ scout (본체)  ──────▶ AWS Bedrock (claude-sonnet-5)
                │
                └── stdio ──▶ scout-net-mcp ──▶ 인터넷
                              (유일한 출구,       npm / PyPI / GitHub
                               allowlist 강제)     OSV / DuckDuckGo
```

본체는 인터넷에 직접 나가지 않는다. Bedrock과 MCP 서버, 두 곳만 호출한다.
이건 사내 보안 요구(인터넷 연결부는 별도 서버로 격리)를 그대로 구조로 옮긴 것이다.

**`scout_net_mcp`는 `scout`를 import하지 않는다.** 이 제약만 지키면 나중에 MCP 서버만 떼어내
사내 DMZ 컨테이너로 올릴 때 코드 수정이 0이다. 이 경계를 uv 워크스페이스가 의존성 수준에서
강제한다 — [05-프로젝트관리](05-프로젝트관리.md).

`GITHUB_TOKEN`도 MCP 서버 쪽에만 둔다. 앱에 크레덴셜을 두지 않는 게 이 구조의 이점이다.
stdio에서 이 경계를 실제로 강제하는 방법(자식 프로세스 `env` 필터)은 [08-설정](08-설정.md)에 있다.

## Bedrock 제약이 설계를 바꾼 지점

### 쓸 수 없는 것

서버측 웹검색 ✗ / 웹페치 ✗ / 코드실행 ✗ / Batches API ✗ / Files API ✗ / Models API ✗ /
MCP 커넥터 ✗ / 자동 프롬프트 캐싱 ✗

### 쓸 수 있는 것

구조화 출력 · strict tool use ✓ / adaptive thinking · effort ✓ /
명시적 프롬프트 캐싱 ✓ / 토큰 카운팅 ✓ / 1M 컨텍스트 ✓

### 결과: 검색을 전부 클라이언트측으로

서버측 웹검색을 못 쓰니 검색이 클라이언트로 온다. 이건 손실이 아니라 개선이었다 —
후보 발견을 레지스트리 검색 API(`npm_search`)로 하면 웹검색 스니펫보다 정확하고,
dossier 수집과 같은 API를 재사용한다.

다만 `method` 후보(아키텍처 패턴, 개발 접근법)는 조회할 레지스트리가 없어서 웹검색이
**유일한** 근거다. 그래서 `web_search`는 절단 대상에서 제외했다
([06-범위와일정](06-범위와일정.md)).

## 기술 결정

| 항목 | 결정 |
|---|---|
| 모델 | `claude-sonnet-5` (Bedrock, 계정에 Sonnet만 해제) |
| LLM 클라이언트 | `langchain-aws` `ChatBedrockConverse` |
| 오케스트레이션 | LangGraph `StateGraph` + `SqliteSaver` |
| 구조화 출력 | `.with_structured_output(Model, include_raw=True)` |
| **인터넷 출구** | **`scout-net-mcp` 워크스페이스 패키지로 격리** (stdio) |
| MCP 클라이언트 | `langchain-mcp-adapters` `MultiServerMCPClient` |
| 검색 엔진 | `ddgs` 라이브러리 + Google backend (품질 비교로 결정, 교체 지점 1곳에 격리) |
| 저장 | 표준 라이브러리 `sqlite3`, ORM 없음 |

`include_raw=True`를 쓰는 이유는 `Verdict`처럼 필드가 많은 스키마에서 파싱이 실패할 때
원본을 잡아 재시도 경로를 두기 위해서다.

## MCP 툴 6종

| 툴 | 대상 | 용도 |
|---|---|---|
| `npm_search(text)` | `registry.npmjs.org/-/v1/search` | **후보 발견 주력** |
| `npm_package(name)` | registry | dossier: 버전·릴리스일·라이선스·deprecated |
| `pypi_package(name)` | `pypi.org/pypi/{n}/json` | dossier: 동일 + yanked |
| `github_repo_health(owner, repo)` | repos + commits + contributors + search/issues | dossier: 마지막 커밋일·archived·기여자 수·스타·이슈 처리율 |
| `osv_query(ecosystem, name)` | `api.osv.dev/v1/query` | dossier: 취약점 + 심각도 |
| `web_search(query, n)` | `ddgs`(Google backend) | **교체 지점.** `method` 후보의 유일한 근거. **사람 승인 필요** |

`github_repo_health`의 **기여자 수는 목록을 받지 않고 `Link` 헤더로 센다** —
`contributors?per_page=1&anon=1`의 마지막 페이지 번호가 곧 인원수다. 전체 목록을
페이지로 다 도는 방식은 기여자가 많은 저장소에서 호출이 수십 회로 늘어난다.
`Link`가 없으면(1명 이하) 응답 배열 길이를 쓴다.

`search` 단계에서는 이 툴들을 ReAct 에이전트가 직접 고른다
([stages/2-search](stages/2-search.md)). 사실 값은 에이전트가 아니라 코드가
`ToolMessage` 원본에서 뽑는다.

### 툴 소비자가 둘이다 — `design`과 `search`

`design`도 같은 툴을 같은 MCP 서버에서 받아 쓴다. 목적이 다르다.

| | `design` | `search` |
|---|---|---|
| 무엇을 얻으려고 | 설계 어휘 · 후보 이름 · 패턴명 | **dossier** (판정 근거) |
| 툴 결과가 `facts`에 들어가는가 | **아니다** | 들어간다 |
| `web_search` 예산 | 실행 전체 3회 | 결정 지점당 5회 |
| 주력 툴 | `npm_search` · `web_search` | `npm_package` · `pypi_package` · `github_repo_health` |

**`design`의 툴 결과는 사실이 아니다** — dossier는 `search`만 만든다. 설계 중에
스쳐본 값을 섞으면 kind 라우팅·top-up을 거치지 않은 사실이 judge의 인용 대상이 되고,
grounding은 통과하는데 후보마다 근거 커버리지가 달라진다
([stages/1-design](stages/1-design.md)).

MCP 서버 쪽은 이 구분을 모른다 — 누가 부르든 "허용된 호스트로 요청을 보내는" 일만
한다. 구분은 앱 쪽 경계다.

### 서버측 공통 인프라

| 장치 | 목적 |
|---|---|
| 도메인 allowlist | 위 6종이 쓰는 호스트만 통과. 밖은 거부하고 감사 로그에 남긴다 (`SCOUT_EGRESS_ALLOWLIST`) |
| 토큰버킷 레이트리미터 | GitHub 5000req/h 등 상한 준수 |
| 디스크 캐시 24h TTL | 여러 실행이 공유 → egress 감소, 재실행이 빨라진다 (`SCOUT_CACHE_TTL_HOURS`) |
| 감사 로그 | 요청 URL + 시각. 보안 경계가 작동한다는 증거 |

### 앱측 승인 게이트 — `web_search`만 (`design`·`search` 공통)

allowlist가 **어디로** 나가는지를 막는다면, 승인 게이트는 **무엇이** 나가는지를 막는다.
외부 검색엔진에는 LLM이 만든 자유 서술 질의가 그대로 나가므로 사내 프로젝트 맥락이
유출될 수 있다. 나가기 전에 사람이 보고 승인·거부한다.

이 게이트는 **앱(`scout`) 쪽**에 있다 — `scout_net_mcp`는 `scout`를 import하지 않고
gaps·승인 개념도 모른다(워크스페이스 경계). MCP 서버는 여전히 "허용된 호스트로
요청을 보내는" 일만 한다.

레지스트리 조회(npm·PyPI·GitHub)는 패키지명·저장소명만 나가므로 승인 대상이 아니다.
자세한 동작은 [stages/2-search](stages/2-search.md) "웹검색 사람 승인" 참고.

### 운영 주의

- **GitHub 토큰**: 미인증은 60req/h, 인증하면 5000req/h.
  프로토타입 규모(후보 8~10개 × 3호출 ≈ 30req)라면 **토큰 없이도 1회 실행은 된다.**
  다만 반복 실행하면 금방 소진되므로 있는 게 낫다. 토큰은 MCP 서버 환경변수로 둔다
- 조회 실패는 예외로 파이프라인을 죽이지 않고 **`gaps` 테이블에 기록**한다.
  judge는 "이 후보는 GitHub 정보를 못 구했다"는 사실을 알고 판단해야 한다
- `web_search`는 `providers/search.py` 한 함수에 격리한다. 사내 검색 API가 생기면
  이 함수만 갈아끼우고 앱은 건드리지 않는다 (`SCOUT_SEARCH_PROVIDER`로 전환)

### 전송

프로토타입은 **stdio**만 쓴다. 사내 배포 시 streamable-http로 바꾸는 건 FastMCP에서 한 줄이다.
