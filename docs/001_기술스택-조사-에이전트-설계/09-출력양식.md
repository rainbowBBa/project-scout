# 09 · 출력 양식

← [문서 목록](README.md)

터미널에 찍는 모든 줄의 규칙. **이 문서가 정본이다** — 화면이 여기와 다르면 코드를 고친다.

CLI가 이 도구의 유일한 얼굴이다. 파이프라인이 몇 분씩 도는데 화면이 멈춘 것처럼
보이거나, 단계마다 표기가 달라 같은 뜻을 다르게 읽어야 하면 결과가 좋아도 쓰기 나쁘다.

---

## ★ 줄 종류 넷 — 각각 다른 질문에 답한다

이게 이 양식의 핵심이다. **줄 모양만 보고 지금 내가 무엇을 해야 하는지 알아야 한다.**

| 모양 | 열 | 답하는 질문 | 예 |
|---|---|---|---|
| `[태그]` | 0 | 지금 어느 단계인가 · 결과가 무엇인가 | `[설계] 단계를 시작합니다.` · `[OK] slug=…` |
| `?` | 2 | **내가 답할 차례다** | `  ? 몇 명 정도가 사용할 앱인가요?` |
| `·` | 2 | **기다리면 되는 것** — 지금 무엇을 하는 중인가 | `  · npm_search "socket.io node.js"` |
| `라벨:` | 2 | 무엇이 나왔나 | `  후보 3개 (자세히: …)` |

`?`와 `·`를 구분하는 이유가 실용적이다 — 앞의 것은 **화면 앞에 있어야** 하고, 뒤의 것은
자리를 비워도 된다. 셋이 같은 모양이면 사용자가 매 줄을 읽어서 판단해야 한다.

---

## 들여쓰기 = 소속

```
[설계] 단계를 시작합니다.                      열 0  배너
  · 설계 탐색 시작 — 툴 최대 10 superstep      열 2  단계 안 (진행)
  설계: 3계층 구조로 …                         열 2  단계 안 (요약 헤더)
  통과 1개 (자세히: scout show <실제slug> design)
    [essential] 실시간 메시지 전달 (feature) — priority 1     열 4  항목
      정할 것: 200 동시 연결·재연결·룸 …                       열 6  항목 속성
      보기: Socket.IO vs 순수 WebSocket vs Server-Sent Events
      힌트: socket.io node.js websocket server, …
[설계] 단계를 종료합니다.
```

열 8은 항목 속성 안의 목록에만 쓴다 (`evaluate`의 후보별 점수).

---

## 기호

| 기호 | 뜻 | 예 |
|---|---|---|
| `—` | 이름과 상세를 가른다 | `socket.io — 실시간 메시지 전달` |
| `·` (문장 안) | 통계 나열 | `걸러낸 요소 2개 · 탈락 후보 3개` |
| `(없음)` | 빈 값 | `힌트: (없음)` |
| `[분류]` | **항상 앞.** 분류·상태만 | `[library]` `[해결]` `[1위]` `[essential]` |
| `→` | 순서 | `무엇부터: 인증 → 스키마 → 전달` |
| `>` | 순위 | `순위: socket.io > ws` |

### 대괄호는 앞에 오고, 분류·상태만 담는다

이 규칙이 없으면 단계마다 위치가 갈린다 — 실제로 그랬다(`[essential] 이름 (kind)` 대
`이름 [library]`). 앞에 고정하면 **줄의 왼쪽만 훑어서 목록을 스캔할 수 있다.**

대괄호에 이름·요소명을 넣지 않는다. 그건 분류가 아니다.

---

## 라벨

- **한글로 쓴다.** 나머지가 한글인데 `gap:`·`근거없음:`처럼 섞이면 읽는 리듬이 끊긴다
- 값이 없을 때 라벨을 지우지 않는다 — `(없음)` 또는 `없음 — 이유`를 쓴다
  (보고서의 불변식 12와 같은 이유: 없는 걸 없다고 말하는 것도 정보다)

---

## "자세히" 힌트 — 실제 slug를 넣는다

```
후보 3개 (자세히: scout show 2026-09-03-team-chat search)
```

한 형태만 쓴다: `(자세히: scout show {slug} {단계})`

**`<slug>` 같은 자리표시자를 찍지 않는다.** 사용자가 그걸 실제 값으로 바꿔 써야 한다는
걸 알 수 없다 — 그대로 복사해서 실행하면 실패한다. 화면에 찍는 명령은 **붙여넣으면
돌아가야** 한다.

---

## ★ 하지 않는 것

| 금지 | 이유 |
|---|---|
| **고정폭 정렬** (`f"{name:<18}"`) | 한글 1자가 터미널에서 2칸이라 **정렬이 실제로 깨진다** |
| **화면에 백틱** | 마크다운 습관이다. 터미널에서는 노이즈고 복사할 때 걸린다 |
| **스피너·커서 되감기** | `search`·`verify`가 `asyncio.gather`로 병렬이라 서로를 덮어쓰고, `web_search` 승인이 **stdin을 읽어** 화면을 다툰다 |
| **자리표시자** (`<slug>`) | 위 참고 |
| **줄 중간에서 끊기는 출력** | 병렬 구간에서 다른 항목의 줄과 섞인다. 줄 단위로 완결시킨다 |

스피너를 안 쓰는 대신 **이벤트마다 한 줄**을 낸다. 부수 효과로 로그로 리다이렉트해도
그대로 읽히고, 나중에 무슨 일이 있었는지 되짚을 수 있다.

> 예외가 하나 있다 — **사람이 답하는 동안은 `·` 줄을 미룬다** (아래 "묻는 동안 진행 줄을
> 보류한다"). 순서는 보존하고 시점만 미루므로 위 표의 금지와 충돌하지 않는다.

---

## 병렬 구간 — 주체를 앞에 붙인다

`search`는 결정 지점을, `verify`는 후보를 병렬로 돌린다. **`·` 줄끼리** 섞이는 건 막을 수
없으니 **어느 항목의 줄인지 보이게** 한다.

```
  · 실시간 메시지 전달 계층 — npm_search "ws websocket library node"
  · 메시지 저장 — npm_search "prisma orm postgres typescript"
  · 실시간 메시지 전달 계층 — 후보 추출
```

★ **수용하는 것은 `·`끼리 섞이는 것까지다.** `·`가 `?`를 밀어내는 것은 수용하지 않는다 —
줄 종류의 우선순위(위 "`?`는 화면 앞에 있어야 하고, `·`는 자리를 비워도 된다")가 그때
깨지기 때문이다. 그 집행 장치가 아래 절이다.

---

## 사람에게 묻는 줄

되묻기와 검색 승인이 여기 해당한다. 둘 다 열 2의 `?` 줄이다 — 단계 안에서 일어나는
일이므로 단계 안에 들여쓴다.

```
[인터뷰] 단계를 시작합니다.
  ? 몇 명 정도가 사용할 앱인가요?: 사내 200명

[검색] 단계를 시작합니다.
  ? 인터넷 검색 "socket.io alternative" — 허용할까요? [y/N]: n
  ? 거부 사유: 고유명사를 질의에 넣지 마세요
  · 인터넷 검색 거부 — 질의를 고쳐 다시 시도한다
  ? 인터넷 검색 "websocket server node" — 허용할까요? [y/N]: y
```

`: `는 `typer.prompt`/`typer.confirm`이 붙인다 — 문구 끝에 콜론을 직접 넣지 않는다.

**화자를 밝히지 않는다.** `인터뷰 봇:` 같은 접두는 뺀다 — `?`가 이미 "당신이 답할
차례"를 말하고, 들여쓰기가 `[인터뷰]` 소속을 말한다.

자동 승인(`--auto-approve-search`)은 질문이 아니므로 `·` 진행 줄이다. **무엇이 나갔는지는
그대로 보여준다** — 승인을 건너뛴다고 내용을 감추면 게이트의 의미가 준다.

### 묻는 동안 진행 줄을 보류한다

`?` 줄이 답을 기다리는 동안 `·` 줄은 **보류된다.** 답이 끝나면 보류분을 **순서대로
전부** 찍는다 — 버리지도 접지도 않는다.

**보류되는 것은 출력뿐이다.** 다른 결정 지점은 그동안 계속 일한다. 사람이 고민하는 동안
이벤트 루프를 멈추면 그 요소들의 in-flight 요청이 타임아웃되기 때문이다.

**승인 문의는 한 번에 하나만 뜬다.** `SearchGate`가 락을 프롬프트 내내 잡으므로 두 번째
요소는 질문을 시작조차 하지 않는다. 그래서 질문이 보류 버퍼에 섞여 들어갈 일도 없다 —
질문은 `?` 프롬프트가 직접 찍고, 버퍼는 `·` 줄만 담는다.

**자동 승인은 보류하지 않는다** — 답할 사람이 없으면 화면을 독점할 근거가 없다.

규칙 한 문장: **stdin을 읽는 함수는 `progress.while_asking()` 안에서 읽는다.**

```
[검색] 단계를 시작합니다.
  · 결정 지점 3개 조사 시작
  · 실시간 메시지 전달 — npm_search "ws websocket library node"
  ? 인터넷 검색 "PG LISTEN NOTIFY vs Redis pub/sub" — 허용할까요? [y/N]: y
  · 메시지 저장 — npm_package "prisma"          ← 답한 뒤에 나온다
  · 인증 — github_repo_health "jose"            ← 보류돼 있던 줄
  · 실시간 메시지 전달 — web_search "PG LISTEN NOTIFY vs Redis pub/sub"
```

이 장치는 커서를 되감지도, 줄을 끊지도, 무엇을 지우거나 접지도 않는다 — **시점만 미루고
순서는 보존한다.** 그래서 로그로 리다이렉트해도 줄이 하나도 사라지지 않는다.

한계: 장치가 감싸는 것은 `·` 줄뿐이다. MCP 서버 서브프로세스의 stderr나 라이브러리
경고는 보류 대상이 아니다.

## 태그

| 태그 | 언제 |
|---|---|
| `[인터뷰]` `[설계]` `[검색]` `[검증]` `[평가]` `[리포트]` | 단계 배너 (`STAGE_LABELS`) |
| `[OK]` | 성공 · 완료 |
| `[FAIL]` | 실패 (`doctor`) |
| `[SKIP]` | 건너뜀 (`doctor`) |
| `[미구현]` | 아직 없는 단계를 지정했다 |
| `[개발]` | **개발 전용 정보** — LLM 캐시 사용·적중률처럼 사용자에게 불필요한 것 |

`[개발]`을 따로 둔 이유는 나중에 한 줄로 걷어낼 수 있게 하려는 것이다.

## 어디에 있나

| 무엇 | 어디 |
|---|---|
| 진행 줄 · 툴 호출 표시 | `scout/progress.py` |
| 배너 · 단계 요약 · 푸터 | `scout/cli.py` |
| 되묻기 | `scout/stages/interview.py` |
| 검색 승인 | `scout/approval.py` |
| **묻는 동안 진행 줄 보류** | `scout/progress.py` (`while_asking()`) — 여는 곳은 `approval.default_approve` · `interview._default_ask` |

보류 장치가 `progress.py`에 있는 이유는 `step()`이 진행 줄의 **유일한 출구**여서다 —
한 군데만 게이트하면 `search`·`design`·`verify`·`evaluate`가 전부 덮인다. 스트림 자체를
버퍼링하는 방식(`redirect_stdout`)은 쓸 수 없다. `?` 프롬프트도 같은 stdout에 쓰므로
**질문이 함께 삼켜진다.**

창을 여는 곳이 공통 경로가 아니라 **stdin을 읽는 함수**인 것도 의도다 — 보류의 근거가
"답할 사람이 화면 앞에 있다"이므로, 묻지 않는 자동 승인은 창을 열 이유가 없다.

진행 줄을 `cli.py`에서 찍을 수 없는 이유가 있다 — `cli.py`는 `stream_mode="updates"`로
**노드가 끝난 뒤에만** 개입한다. 노드 안의 툴 루프·항목별 루프는 거기서 보이지 않으므로
단계 안에서 찍는다. `interview`의 되묻기와 `web_search` 승인이 이미 그렇게 한다.
