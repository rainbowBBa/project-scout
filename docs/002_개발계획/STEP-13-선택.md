# STEP 13 · 선택

> 여유가 있을 때만 손댄다. 001의 절단선을 역순으로 되돌리는 순서다.
> **없어도 프로토타입은 완성이다.**

**선행** STEP 12 · **시간** 여유분 · **설계** [06-범위와일정](../001_기술스택-조사-에이전트-설계/06-범위와일정.md)

## 되돌리는 순서

| 순위 | 항목 | 얻는 것 |
|---|---|---|
| 1 | `osv_query` provider | `risk` 점수에 취약점 근거가 붙는다 |
| 2 | `method` kind 후보 | 아키텍처·개발방법도 후보로 판정된다 |
| 3 | grounding 재판정 루프 | 위반 시 다시 물어본다 (검출만 → 교정까지) |
| 4 | `--from` 실제 건너뛰기 | 프롬프트만 고쳐서 한 단계를 다시 돌릴 수 있다 |
| 5 | `--max-components 8` 로 풀 규모 1회 | 비교의 값이 실제로 올라가는지 확인 |

## 완료 기준 (착수한 것만)

- [ ] `osv_query` — `osv.vulns`·`osv.max_severity` 가 dossier에 들어간다
- [ ] `method` 후보 — `gaps`에 "레지스트리 없음"이 기록되고 `confidence`가 `low`로 나온다
- [ ] grounding 재판정 — 위반 목록을 프롬프트에 넣어 1회 다시 묻는다
- [ ] `--from` — 지정한 단계 앞의 노드를 실제로 건너뛰고, 그 단계는 **다시 돈다**
- [ ] 풀 규모 — 후보 30~40개, judge 30~40회가 쿼터 안에서 돈다

## 4번이 새로 들어온 이유

`--from`은 지금 값만 검증하고 아무 일도 하지 않는다 —
재개는 전적으로 `SqliteSaver` 체크포인터가 한다(끝난 노드를 건너뛴다).
그래서 **프롬프트만 고쳐서 `design`을 다시 돌리는 게 안 된다.** 체크포인트가 그 노드를
이미 끝난 것으로 보기 때문이다. 지금은 새 slug로 돌리거나
`runs/<slug>/checkpoints.sqlite`를 지운다.

001은 이 장치를 "가장 자주 쓰인다"고 적었고, 파일 저장을 택한 근거이기도 했다
([03-저장](../001_기술스택-조사-에이전트-설계/03-저장.md)). `design`·`evaluate`의
프롬프트를 반복 튜닝하게 되면서 없는 게 실제로 불편해졌으므로 절단선 되돌리기에 넣었다.

구현은 해당 노드의 체크포인트를 무효화하는 방향이다 — 001이 잘라낸
"체크포인트 무효화 로직"이 이 자리다.

## 막히면

1번을 먼저 한다. provider 하나 추가라 30분이고, `risk` 점수의 근거가 가장 눈에 띄게 좋아진다.

4번은 겉보기보다 크다 — 체크포인트 무효화는 LangGraph의 내부 표현을 건드린다.
새 slug로 돌리는 우회가 있으므로 1~3번보다 뒤에 둔다.

5번은 Bedrock 동시 호출 쿼터에 부딪힐 수 있다 — `Semaphore`를 조인다.
